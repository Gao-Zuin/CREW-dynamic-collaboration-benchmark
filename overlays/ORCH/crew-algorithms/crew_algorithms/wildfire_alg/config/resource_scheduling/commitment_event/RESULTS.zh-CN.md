# DeepSeek Flash 单例运行：新增五名平民，再出现邻近火点

配置：`FiveCiviliansAt80_75AfterOriginalFireDozerMovesThenFireAt80_80_WorkerReport`，seed 42，动态组织，26 步，11 名 worker。请求模型名为 `deepseek-v4-flash`，API 响应名为 `deepseek-flash`。worker 和组织者调用都关闭思考输出；同一步 worker 模型调用并行，消息下一步投递。2026-11-10 运行，日志在本机 `benchmark_runs/commitment_event_deepseek_v4_flash_corrected_seed42_20261110/`；仓库另存有 `workspace/benchmark_runs/commitment_event_deepseek_v4_flash_corrected_seed42_20261110/events.jsonl.gz`，可解压后用 `scripts/analyze_commitment_event_run.py` 复核。精简结果见本任务目录的 `deepseek_v4_flash_seed42_adaptive_result.json`。

| 事实 | 新平民 `(80,75)` | 新火点 `(80,80)` |
|---|---:|---:|
| 提交事件 | 第 8 步，`condition_met` | 第 14 步，距前事件 6 步 |

第 0 步原火组的推土机发生位移，第 1 步执行清树动作，环境累计清树数由 0 增至 16；第 8 步原火活跃、初始获救人数为 0，因此首事件确实按状态触发。触发器本身只要求位移，清树由轨迹另行核实。组织者共提交 9 次成员图，其中第 14 步与第 15 步发生事件后的成员变化，但两次新事件的坐标均未由组长上报组织者，不能把这些变化归因于新事件。worker 的报告明确要求组长通知组织者；组织者后续仍主要处理原火 `(22,50)` 一带。这个实例展示了**信息已到组长，却未落实到中心决策**的失败点。

第 25 步终局：全局获救人数 0 / 10，火势仍活跃，灭火数 0，累计清树 133，毁损 agent 1，整体任务失败。新增平民实体数、新增平民获救数和新火点分区扑灭情况不能由现有全局奖励独立确定，摘要保留为空值。最近职业的移动下界仅证明接近目标有时间余地，不证明完整救援与扑火可行；仍需成功的参考调度轨迹。

资源开销：1128 次 API 调用，输入 3,860,911 token，输出 227,532 token。8 次组织者响应中 1 次因成员约束被拒，其余提案可解析。此前一条同任务轨迹因组织者调用未关闭思考输出，33 次响应中 31 次达到 4096 token 上限并解析失败；它只用于定位配置错误，不作为模型协作能力结论。该轨迹第 15 步曾在来源限定的局部视野中出现新火格和平民格，支持事件注入确有物理效果，但不能证明实体数或救援完成。

下一步最有价值的验证：从相同第 8 步状态分别运行“组长强制转发新事件”和原协议，保持模型与后续调度器一致，隔离信息传递失败的影响。随后补独立实体 ID 与分区火势计数，并以一条成功的脚本调度轨迹验证完整物理可行性。

## 组织者直接收到通知：40 步运行

配置改为 `FiveCiviliansAt80_75AfterOriginalFireDozerMovesThenFireAt80_80_OrganizerDirect`，同 seed 42、动态组织与模型设置，延长到 40 步。第 8 步新增平民、第 14 步新火点仍按预期释放。组织者分别在第 8、14 步收到官方坐标通知，并在第 9、15 步的模型输入中看到坐标；相应方案也在第 9、15 步提交。无人机来源限定的局部视野分别于第 11、14 步看到新增平民区域和新火点，仍不能证明实体数。

第 9 步方案已把 `(80,75)` 写进救援组目标，但成员表未变化；第 15 步方案因 `(80,80)` 与平民区接近，让唯一的无人机 10、直升机 11 同时服务原火组与东部救援/新火组。全部 36 次图提交中，13 次真正改变成员或组长关系，其中 3 次只因成员离线；提交次数不能直接当作有效重组次数。

第 39 步终局仍失败：全局获救 0 / 10，火势仍活跃，累计灭火 25、清树 161、毁损 agent 4。灭火 25 是全局奖励，无法归到新火点。第 25 步截面与上述 WorkerReport 26 步轨迹相同，双方获救数均为 0、火势均活跃；直达组当时累计灭火 0、毁损 agent 2，WorkerReport 组为灭火 0、毁损 agent 1。直达通知显著缩短了组织者获知新坐标的时间，但本例没有显示完成效果提升。

本次运行 1619 次 API 调用，输入 6,420,063 token，输出 377,400 token。详细逐事件结果见 `deepseek_v4_flash_seed42_organizer_direct_40step_result.json`，压缩原始事件日志见仓库的 `workspace/benchmark_runs/commitment_event_organizer_direct_40step_seed42_20261110/events.jsonl.gz`。两条轨迹的时长不同，且 WorkerReport 轨迹采集于最新组长提示词修改之前；这是一组诊断性对照，不能单独用作组织方式收益的因果结论。
